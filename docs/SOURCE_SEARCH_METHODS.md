# China Atlas 信息来源与检索维护指南

核对日期：2026-09-21。本文说明**目前实际采用了什么方法、证据存在哪里、今后如何接入采集**。下文数量是人物背景试点加入前的 456 条来源基线；最新数量及 host 清单见可重跑的[来源盘点报告](SOURCE_INVENTORY.md)和[逐条 JSON](../reports/source-inventory.json)。它不是全网爬虫已上线的说明，也不表示列出的每个网页今天都重新访问了一遍。

## 1. 现在实际做到哪里

基线盘点读取公开仓库当时 `data/atlas.json` 的全部来源记录，并对照维护版 `server.py`、`registry.py` 和济宁扩充原文档案。以后新增来源，运行 `python3 scripts/source_inventory.py` 更新报告，不需要手工重填本文的历史基线。

| 盘点项 | 试点前基线 | 如何理解 |
| --- | ---: | --- |
| 来源 ID | 456 | 一篇文章可能因不同研究批次有多个 ID |
| 唯一 URL | 428 | URL 不同仍可能是同源转载 |
| 不同 host | 158 | 例如市政府、应急局是不同子域名 |
| 网站家族 | 98 | 按域名及少量明确的媒体品牌归组，用于维护，不是独立性判断 |
| 标有本地摘录的来源 | 249 | `has_local_evidence` 字段统计；未标记不等于原文一定不存在 |

现有资料主要通过**AI 协助检索 → 阅读原文 → 保存原文和摘录 → 整理区域数据包 → 复核身份、职务、日期 → 合并发布**得到。济宁扩充另有按人大任免栏目批量收集、解析历史公告的工作；这是一轮有范围的研究，不是长期后台任务。

目前唯一写在维护版服务器中的自动外部新闻刷新源是[共产党员网人事任免](https://www.12371.cn/special/rsrm/)。服务器启动、读取新闻接口、手动刷新时可能触发后台请求；普通请求距上次尝试不足 24 小时不重抓，强制刷新也有 30 秒间隔。它只提取该站有日期的文章标题和链接，保留缓存；**没有每天固定时刻的调度器，也不会把新闻自动变成人物现任职务**。

维护版另有“准备核对 → 选择应用”的任免审阅流程：读取用户指定的支持来源，解析已支持的任免语句，生成待审记录，经确认后写入可回滚台账。它不是任意网站通用爬虫，也不是无需复核的 LLM 自动入库。GitHub Pages 只有审核后的静态快照，不运行这个服务器。

### 新闻媒体

当前已用新华社（`news.cn`、`xinhuanet.com`）、人民网、山东广播电视台齐鲁网、大众网，以及少量澎湃、地方报纸等公开报道。优先用途是**发现变动、补公开履历、补近期具名活动**。

基线来源分组示例：新华社相关域名共有 41 条 source ID，人民网家族 36 条，大众网 10 条，齐鲁网 9 条。这些数字是维护清单规模，不是独立报道数量。

实际检索中也会遇到搜狐、百科、搜索摘要等结果。能追到官方原文的，优先引用原文；只剩转载时记录原始发布者和转载链，注明原文可读性。当前库有少量转载类来源，不能将“链接可打开”等同于“事实已经确认”。

### 学术资源与百科

当前记录了 [UC San Diego CCP Elites 数据目录](https://chinadatalab.ucsd.edu/resources/ccp-elites-database/)、[China Data Lab 展示及方法页面](https://chinadatalab.ucsd.edu/viz-blog/the-makeup-of-the-ccp-elite-update/)和 [CFPS 行政／管理职务变量方法文档](https://www.isss.pku.edu.cn/cfps/docs/20191025120406491438.pdf)。用途是了解已有数据与编码思路；**没有证据表明已经系统下载、清洗并导入这些学术数据库**。

试点前基线的 456 条公开来源记录中，**没有百度百科或维基百科 URL**。这不表示研究中从未看见百科线索，而是不能说“数据库已接入百科”。将来可用百科发现旧职、拼写和参考文献，实际入库仍追溯其引用；不把编辑页面的更新时间当任职日期。地方高校的公开活动报道归为“机构新闻”，不因为域名是大学就称为学术数据。

## 3. 当前实际检索方法

### A. 先定机构和范围，再找人

先列市级部门、县市区、功能区，再查“领导信息／领导分工／机构职能／选举任免”。不要从一张人名表直接创建全部人物。一次以一个部门或一组任免公告为边界，记下已覆盖、缺口、不可读页面。

已经采用的查询形式包括：

```text
site:jining.gov.cn "济宁市应急管理局" "领导"
site:business.jining.gov.cn "领导信息"
site:jiningrenda.jining.gov.cn "任免名单" "2026"
site:jining.gov.cn "王雪尽" "2026"
site:jining.gov.cn "周媛" "任命"
"济宁市消防救援支队" "支队长" "2026"
site:sdcourt.gov.cn "嘉祥" "院长" "2026"
```

“人名＋单位＋年份”用于核对近期职务；“人名＋任命／免去／调任／辞职”用于查任期边界；“人名＋不同单位”用于找冲突和同名。以上是可复用的查询格式，不是保证召回全部公告的检索规则。

### B. 搜索结果只负责指路，取证必须读正文

1. 打开原文，确认真实发布网站、正文标题、发布机构、发布日期。
2. 另读正文中的会议日、决定日、生效日。例如“27 日发布、23 日召开”必须分别记。
3. 定位包含“姓名＋准确职务”的句子；保留最小够用摘录和所在页面。不能把搜索摘要的省略部分自行补全。
4. 保存原始 HTML 或 PDF、提取文本、来源 URL、抓取结果；对本地档案记录 SHA-256。全文只留维护端，公开端保留短摘录和原链接。
5. 若目录页面看似空白，检查原始 HTML：本次实际遇到过脚本中嵌入文章链接、栏目跳转、分页数据以及导航片段。读取其中公开的链接或页面内容，并再次访问原文章；不把导航年份或模板更新时间当正文日期。
6. 打不开时保留失败状态。可找另一官方转载、公开缓存线索或后续报道；仍缺正文时标为待核，不能用“搜得到”替代“已核”。

实际使用了联网检索工具，以及直接 HTTP 获取已知公开 URL、HTML 文本提取和有范围的目录解析。没有采用登录后资料、内部通讯录或私人联系方式来补本库。

### C. 按“每条职务”核验，不给整个人一次盖章

- 官员 A 的副局长职务被新报道确认，不会顺带确认旧目录中的调研员职级、另一个单位的局长兼任。
- 党组书记、行政局长、下属单位主任分条；一个人可以同时有不同证据日期和不同核验状态。
- 任前公示是拟任，不能当已经正式任职；批准辞职、免职、调任各按原文解释。
- 同名先保留稳定身份 ID 和待确认候选。核对履历、出生年月、旧单位、明确调任材料后才能合并。
- 近期目录和旧任命冲突时不简单“多数票”。比较原文性质与日期，保存双方证据及未决问题。
- 共事需要可支持的任职时间交集；同地工作、同场参会都不能自动解释为认识、派系或私人关系。

当前新济宁资料采用 **180 天证据新鲜度门槛**：超过门槛而无新确认的近期职务证据可降为历史待续核；这是本资料库维护规则，不表示已离任。具体字段定义见 [DATA_MODEL.md](DATA_MODEL.md)。

### D. 同源转载不能算独立验证

先按规范化 URL 去重，再看文章署名、首发机构、日期、正文是否相同。市政府转应急局原文、媒体转新华社通稿、搜索引擎展示同一文章，通常属于同一事实来源链。两处政府目录也可能使用同一后台数据，不能因为域名不同就认定是两次独立核准。

可保留多个镜像链接提高可访问性，但证据统计应区分：原始文件、原文转载、独立采访／独立履职报道。将来的来源清单建议加入 `origin_source_id` 或 `reprint_of`，当前数据尚未全面标注这层关系。

## 7. 每次维护的最小检查

- 新来源链接能否对应到正文及发布机构；旧源失败有没有保留记录？
- 事件日、发布日期、查阅日是否分开？
- 职务是否精确到机构；等级、兼任是否有自己的证据？
- 是否有同名、旧目录、新免职或来源冲突尚未解决？
- 是否把转载或同一 URL 的多个 ID 当成了独立证据？
- 未覆盖范围是否写入缺口，避免误读为“单位没人”或“已全部录完”？

审阅完成再入库、导出和发布。定期采集的价值是减少寻找原文的时间，不能替代这些事实核对。
