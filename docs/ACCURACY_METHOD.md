# 人物资料怎样核实

**核实单位是“一条事实”，不是“一个人”。** 一个人的现任职务可能已核实，出生年月有可靠公开简历，另一个兼任却只见于旧目录。三者分别保存证据和状态；不生成看起来精确却无依据的“准确率 98%”。

## 已实现的检查

运行只读检查，不请求网络、不改变人物或私人笔记：

```sh
python3 scripts/audit_data.py
python3 scripts/accuracy_report.py --as-of 2026-09-21
```

第二条命令的日期应改成实际研究时点。默认 180 天复查间隔可以用 `--stale-days` 调整。输出 [复核摘要](ACCURACY_REPORT.md) 和 [完整队列](../reports/accuracy-report.json)，记录输入资料与摘录的 SHA-256，便于重现结果。它检查的是一致性和证据缺口，**没有联网重新核实全部原文**。

| 检查层 | 检查内容 | 处理方式 |
| --- | --- | --- |
| `error` | 重复 ID、失效引用、无效日历日期、明确反向任期、已结束却标现任、现任与未核实状态矛盾 | 修正后才能发布；进程返回非零退出码 |
| `review` | 已记录冲突、同名候选、证据过旧、证据时间在研究日之后、同字段有不同已核实值 | 对照原文；可能是精度不同，不自动定错、不合并身份 |
| `gap` | 职务缺证据类别或时点、来源缺短摘录/类型、旧日期混有解释文字 | 补齐可审计性；不能据此判断人物虚假或已经离任 |
| `info` | 多个 source ID 指向同一页面 | 允许不同段落引用，但不算独立支持 |

年份、月份、日期按其真实精度比较。例如“2025 年任职”和“2025 年 3 月卸任”不一定矛盾；“2025-04（公开报道确认）”不能直接截成正式任命日。查阅时间 `checked_at/accessed_at` 不代替事件日或角色证据日。

网络记录另查人物端点、引用履历、机构、地区与来源是否对应。同机构共事必须有两条可界定的任期；缺少起点或开放任期的独立具名证据日列为 `gap`，不能用查阅日补齐。已知结束的任期完全不相交是数据逻辑错误；月/年精度下可能交接却标为确定共事，以及关系延伸超过证据时点，列为 `review`。超过证据时点不等于已经离任。“同地经历”不要求同期，公开同场活动另存自己的事件日期。

来源和摘录的日期也检查日历有效性及未来时点。发布日期晚于查阅日、摘录与来源的 URL 或发布日期不一致均只提示复核，可能涉及预告、页面更新或重定向；不据此自动判定人物事实有误。不存在的来源、摘录 ID、转载引用和网络端点列为 `error`。履历的 `status`、`is_current` 与核验类别分别检查，不把拼写错误默认为历史状态。

现有检查不覆盖所有语义错误：一段摘录是否真的支持某职务、是否漏掉后来的免职、两个不同网址是否转载同一通稿，都需要下一层复核。角色与履历尚未全面绑定稳定 `role_id`，不会用模糊标题匹配自动改任期。网页 404、超时与事实错误是不同问题。

`status_events` 另按[人物状态合同](PERSONNEL_STATUS_MODEL.md)检查：人物/机构/来源引用、原子动作分类、必需公告与核对日期、无源事件、重复 ID 及显式更正链。未来核对日是 `error`；未来公告/生效日为 `review`，不得直接当作已发生状态。年月精度与研究日重叠时不误报确定未来。待核/冲突事件保留为 `review`；调查、党纪、军籍、司法事件均不自动改任职或推断定罪。

## 事实核验步骤

1. **确认身份。** 姓名只是检索词，结合原单位、出生年月、完整简历或明确调任公告。已确认不同人的张斌、张海波保留独立 ID。
2. **拆开具体主张。** 党组书记、局长、副局长、职级分别对应机构和原句；不能用一条具名报道确认所有兼任。拟任公示仍然是拟任。
3. **找原始依据。** 正式任免/选举决定用于岗位变化；官方简历用于背景；具名活动用于某日仍以该身份出现。目录有覆盖面，但可能陈旧。媒体引用简历可收录，明确标明转载来源。
4. **主动找反证。** 同时搜索“人名＋单位＋免去／辞职／调任”，对照新公告和旧目录。按事件时点和文书性质解决冲突，不按网页数量投票。
5. **留最小充分摘录。** 保存原句、正文日期、查阅日期和本地原文校验值。搜索摘要只作线索；原文缺失保持待核。来源通过并不证明来源从未写错。
6. **先审阅再更新。** 变更保留旧值、来源、新值、理由、核对日。历史岗位不能被新岗位抹掉；新岗位也不自动结束另一个党内职务。事实缺失不代表不存在。

每次发布优先复核现任变化、同名身份及来源冲突；再按单位/来源类型抽查普通记录，防止只检查“容易核对的领导”。抽查应记录选取规则、样本量、发现错误数及修正，不把小样本通过推广成全库准确率。目前这套抽样流程仍需维护者执行，未实现自动事实裁决。

## 更详细的背景字段

新增 `profile_facts`，每条含稳定事实 ID、人物 ID、字段、展示标签、值、来源、短摘录、证据日期、核对日期和核验状态。来源日期只说明依据时点，不是出生/入党/毕业日期。

- `birth_date`：出生年月，保持原文精度，不补具体生日。
- `native_place`：籍贯或原文“某地人”，不当作出生地。
- `education`：学习经历、学历、学位分条；在职与全日制只录明确表述。
- `work_started`、`party_joined`：参加工作、入党时间分别记录。
- `career_background`：公开历史经历片段。没有任期边界的片段暂不生成确定共事边。

首批采用温金荣、郭飞、庞建栋三个档案试点。未取得郭飞学校、庞建栋出生及学历的可靠原文，保持未收录。温金荣的“1996 年参加工作”和“1992—1997 年就读”按来源并列，不擅自改成年份一致。显示“原文支持”指读到来源直接表述，并非获得人事档案认证。

百科和公开数据库可以补充检索路径：保留条目 ID、版本/访问时间、原引用，再追溯原始材料。多个网站照抄同一简历仍是一条来源链。字段不同版本冲突时保留并列记录和说明，不能把后抓取的版本当作必然正确。
